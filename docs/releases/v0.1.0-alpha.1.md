## Riesgos residuales

1. El tag inmutable conserva el commit anterior al fix del bucket de rate
   limiting. Para una recuperación operativa con CI verde se debe aplicar
   `d8c1b1c` después de crear la rama desde el tag.
2. El mensaje del tag preexistente es `Baseline técnico endurecido`, más corto
   que el texto previsto en el programa. No se recreó porque modificar un tag
   publicado rompe su inmutabilidad.
3. Faltan iconos PWA aprobados de 192 × 192 y 512 × 512; el manifiesto mantiene
   `icons: []`.
4. Falta completar una pasada visual con navegador real y lector de pantalla.
5. El posible clipping del menú de acciones requiere esa verificación visual
   antes de introducir un portal o popover.
6. Las 12 vulnerabilidades npm de desarrollo dependen de actualizaciones
   compatibles de paquetes upstream.

## Recuperación

1. Ejecutar `git fetch --all --prune`.
2. Verificar que `git rev-parse v0.1.0-alpha.1^{}` devuelve
   `d2c4558b16144e4bc1c7998bb523d47e5f1f906e`.
3. Crear una rama recuperable sin modificar `main`:
   `git switch -c recovery/v0.1.0-alpha.1 v0.1.0-alpha.1`.
4. Para recuperar también el CI corregido, aplicar
   `git cherry-pick d8c1b1c122424e240e2daedd547659c7089ea53f`.
5. Instalar dependencias bloqueadas, migrar una base aislada y ejecutar las
   suites completas antes de desplegar.
6. Levantar `docker compose up -d --build` y repetir los smoke tests anteriores.
7. Si la verificación falla, conservar datos y volúmenes, detener el despliegue
   y volver a la imagen previamente aprobada; no reescribir historial ni mover
   el tag.
